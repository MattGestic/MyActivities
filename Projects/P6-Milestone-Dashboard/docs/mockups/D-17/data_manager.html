D-17 data manager: mockups for sign-off

Static mockups only, no app code changed. Restyles the Settings drawer's Sources and Annotations tabs, the User-defined grid, the reporting-period control, and the D-18 board edit mark, to the D-16 design standard (24px desktop controls, 32px touch, tokens, type ramp, field row pattern). Source: the D-17 Data manager plan and its addendum. Reference for control conventions: docs/mockups/D-16/component_sheet.html.

1. Sources tab (D-17a)

Tabs become Sources · Annotations · Import · Defaults. Each schedule layer is one row: name, data date, row/milestone counts, an on/off switch, Rename, Remove. Off means the source's rows leave the board; its annotations and filter entries stay. The embedded baseline is shown locked, never toggled. User-defined milestones are a source like any other: same row shape, with Manage… to open the grid and a schedule-format export so they round-trip through the importer. Two enabled sources sharing an Activity ID raise a one-line warning rather than silently overlapping.

2. Annotations tab (D-17b preview)

Consolidates the exports that are today scattered across More Actions and the action bar into one named list, each with its purpose stated in one line. Mounting is a stack of layers rather than one slot: Local edits sits on top and cannot be removed, only exported; each mounted file below it shows its counts, an on/off switch, Merge into Local edits, Remove, and, where it changes an earlier file's value, an override note. Order is oldest first, later overrides earlier. Merge folds a file into Local edits so the two become one set; the file leaves the list and the merge cannot be undone, so it asks first. Where Local edits already holds a value for the same field, the local value is kept, so merging never changes what an on layer already shows.

3. Reporting period control (D-03/D-04 preview)

Its own pill at the start of the header meta line, so it reads as a control rather than a caption. Filled accent means the current period; an outlined amber pill means a historic one is being viewed. The dropdown offers a one-click "New period" for the next week ending, every period with entries newest first, and a date picker for anything else. Writing into a historic period shows a banner on the card so the choice is explicit, and every entry's period tag opens a small "Move to" menu, alone or in bulk from the Annotations tab.

4. User-defined grid, "the sheet" (D-17c preview)

A native editable table, no Tabulator, no new dependency. Opens full height from Sources > User-defined > Manage…. One cell shown mid-edit with the focus ring the standard specifies. Desktop only for this mockup: on a phone the sheet scrolls horizontally inside its own frame, the header actions stack, and the rest of the drawer is unaffected, the same pattern .pg-scroll uses on this page for anything wider than the viewport.

5. Board edited mark (D-18 preview)

When the effective Finish/Start date or the status/health comes from a user override rather than the source, the marker gets a small * beside its icon: the same glyph as the card's saved-edit mark, at the icon's top right, in accent ink, outside the icon so the shape and fill never change. A date override that moves the marker to a different week keeps a faint ghost tick at the source week. It reads the effective value against the source, so it cannot drift from the card.
